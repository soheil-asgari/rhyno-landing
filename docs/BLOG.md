# Blog ("مقالات") — authoring and operations guide

The blog is fully generated by the existing static build. You add a Markdown
file (and optionally an image); `npm run build` produces the pages, the
image variants, the sitemap entries, the RSS feed and all internal links.

- Articles live in `content/articles/`
- Output is `/blog/<slug>` in `dist/`
- Nothing about the blog is hand-written HTML

---

## 1. Daily workflow

```bash
# 1. scaffold a new article (creates the file with front matter + headings)
npm run new-article -- payroll-common-mistakes "پنج خطای رایج در محاسبه حقوق"

# 2. add a cover image with the SAME basename
#    content/articles/payroll-common-mistakes.jpg

# 3. write the article (see the template it generated)

# 4. preview
npm run build
npm run serve          # http://127.0.0.1:3000/blog

# 5. verify before pushing
npm run qa

# 6. commit
git add content/articles && git commit -m "post: payroll common mistakes"
```

The build prints a report for every article: the auto-links it created, the
related articles it picked, the modules it associated, and whether the cover
came from your file or the generated fallback.

### Slug rules

`<slug>` must be **lowercase English letters, digits and hyphens** and becomes
the URL: `content/articles/financial-close.md` → `/blog/financial-close`.
A Persian or uppercase slug fails the build with a clear message.

## 2. File and front matter reference

Front matter is **optional**. Everything has a default.

```markdown
---
title: "بستن دوره مالی بدون استرس"        # default: first H1 in the file
description: "چک‌لیست عملی برای بستن ماهانه"  # default: first paragraph, ~155 chars
date: "2026-01-12"                        # default: file's first git commit date
updated: "2026-02-01"                     # optional, shown as "به‌روزرسانی"
category: "مالی و حسابداری"                # default: "عمومی"
tags: ["حسابداری", "بستن دوره"]           # optional
image_alt: "نمای بستن دوره در راینو"       # default: the title
modules: ["finance", "reports-search"]    # optional, module slugs
draft: true                               # optional, keep out of the site
autolink: false                           # optional, disable auto internal links
---

# بستن دوره مالی بدون استرس

مقدمه…
```

| Key | Type | Notes |
|---|---|---|
| `title` | string | If omitted, the first `# H1` is used **and removed** from the body so the page has exactly one `<h1>`. |
| `description` | string | Used for `<meta name="description">`, cards and RSS. |
| `date` | `YYYY-MM-DD` | Publication date. Also drives ordering and the Jalali label. |
| `updated` | `YYYY-MM-DD` | Optional. Adds a "به‌روزرسانی" line and `dateModified`. |
| `category` | string | Persian name; mapped to an ASCII slug via `docs/data/blog-taxonomy.json`. |
| `tags` | list | Persian names; also mapped via the taxonomy file. |
| `image_alt` | string | Alt text for the cover. Defaults to the title. |
| `modules` | list | Module slugs (e.g. `finance`). Invalid slugs are ignored with a warning. |
| `draft` | boolean | `true` hides the article everywhere. |
| `autolink` | boolean | `false` disables automatic internal links for this article. |

**Invalid front matter fails the build.** Unknown keys, duplicate keys, a
non-`YYYY-MM-DD` date, or a `true`/`false` written as a string are all
reported with the file name and line number.

### Markdown support

GitHub-flavoured Markdown: headings, lists, tables, blockquotes, fenced code,
inline code, bold/italic, links and images. Raw HTML passes through.

- `##` and `###` headings get stable ASCII anchors and feed the table of
  contents (rendered only when there are **3 or more** of them).
- Tables and code blocks are wrapped in horizontally scrollable containers and
  set `dir="ltr"` where appropriate, so English text and code render correctly
  inside RTL Persian copy.
- Body text is limited to ~70 characters per line with generous line height
  for comfortable long-form reading.

## 3. Image requirements

| | Recommendation |
|---|---|
| Cover file | `content/articles/<slug>.jpg` (also `.jpeg`, `.png`, `.webp`, `.avif`) |
| Size | **1600×900 or larger**, landscape |
| File size | **under 2 MB** |
| Body images | any name, referenced relatively: `![alt](./<slug>-2.jpg)` |

What the build does automatically:

- Generates **AVIF + WebP + JPEG** at 480, 800 and 1200 px wide (never
  upscaling), with content-hashed filenames in `dist/blog/img/<slug>/`.
- Emits `<picture>` with `srcset`/`sizes` and explicit `width`/`height`
  (no layout shift).
- List cards load covers `lazy`; the article cover is `eager` with
  `fetchpriority="high"`.
- Creates a **1200×630 OG image** (cover, cover-fit) referenced by
  `og:image` and `twitter:image`.
- Processes body images the same way (always lazy) and warns when `alt` is
  empty.

**A missing cover does not break the build** — a brand-coloured fallback with
the title is generated and a warning is printed. Referencing a **local body
image that does not exist fails the build**.

Processed images are cached in `.cache/` keyed by the source file hash, so
rebuilds with unchanged images only copy files. `.cache/` is git-ignored and
safe to delete at any time.

## 4. Automatic internal links

`docs/data/internal-links.json` maps Persian phrases to target URLs:

```json
{ "phrase": "سامانه مؤدیان", "href": "/modules/tax-mowadiyan" }
```

During the build, in article bodies only:

- the **longest phrase wins** (so "مالیات و سامانه مؤدیان" beats "سامانه مؤدیان"),
- only the **first occurrence** of each phrase is linked,
- at most **5 auto-links per article**,
- never inside headings, existing links, code blocks, image alt text or the TOC,
- never to the page you are already on,
- matching is Persian-aware: ZWNJ variants, Arabic `ي`/`ك` vs Persian `ی`/`ک`,
  and Persian vs Latin digits are all normalised, with whole-word boundaries.

To add keywords, append entries to `links` in that file. To opt an article out,
set `autolink: false` in its front matter.

The auto-links found in an article also decide its **related modules** box
(unless `modules:` is set explicitly), and each `/modules/<slug>` page shows up
to 3 latest articles that reference it.

## 5. Scheduling and drafts

- `draft: true` → excluded from pages, lists, category/tag pages, sitemap, RSS
  and search.
- A `date` **in the future** is treated the same way.

> **Scheduled posts only appear when a build runs on or after that date.**
> On Vercel that means the next deploy after the date — either a git push or a
> scheduled rebuild. If you rely on future dates, add a daily cron deploy.

The build reports both cases at the end:

```
blog — 1 excluded: my-post (draft), next-post (scheduled for 2026-12-01)
```

## 6. Taxonomy slugs

Categories and tags are Persian in the front matter but need stable ASCII URLs.
`docs/data/blog-taxonomy.json` holds the mapping:

```json
{
  "categories": { "مالی و حسابداری": "finance" },
  "tags": { "حسابداری": "accounting" }
}
```

An unmapped name falls back to a transliteration (then a hash) **and prints a
warning telling you to add a mapping**. Add the entry to keep the URL stable —
changing a slug later breaks links and search rankings.

Category and tag pages are only generated when they contain at least one
published article.

## 7. Generated output

| URL | What it is |
|---|---|
| `/blog` | Article list, newest first, 12 per page |
| `/blog/page/2` … | Pagination, with `rel="prev"`/`rel="next"` and per-page canonical |
| `/blog/<slug>` | Article page |
| `/blog/category/<slug>` | Category listing (only if ≥ 1 article) |
| `/blog/tag/<slug>` | Tag listing (only if ≥ 1 article) |
| `/blog/feed.xml` | RSS 2.0, latest 30 articles, absolute URLs |

Each article page has: one `<h1>`, breadcrumbs, Jalali publication/update
dates (with ISO `<time datetime>`), reading time, a TOC when there are 3+
headings, the cover image, related articles, a related-modules box, tag links,
a demo CTA, and `Article` + `BreadcrumbList` JSON-LD.

`sitemap.xml` includes every article, list, category and tag page with
`<lastmod>`.

## 8. QA

`npm run qa` covers the blog automatically:

- **links** — every internal link resolves; every article appears in the
  sitemap exactly once; article JSON-LD parses and has the required fields;
  `og:type=article` and `article:published_time` present; images have `alt`;
  heading anchors are unique; TOC links resolve; no auto-link inside a heading.
- **structure** — one `<h1>`, no skipped heading levels, no duplicate ids,
  valid JSON-LD.
- **layout** — no horizontal scroll at 360/375/768/1280/1536 and no missing
  image dimensions, on every blog page discovered in `dist/`.
- **interaction** — blog index renders cards, an article page has a working
  TOC and an eager cover.

## 9. Troubleshooting

| Message | Fix |
|---|---|
| `slug "…" is invalid` | Rename the file: lowercase English, digits, hyphens only. |
| `duplicate slug "…"` | Two files share a basename (any subfolder counts). Rename one. |
| `unknown front matter key "…"` | Only the keys in section 2 are allowed. Check spelling. |
| `"date" must be YYYY-MM-DD` | Quote the date: `date: "2026-01-12"`. |
| `empty body` | The file has front matter but no content below it. |
| `image referenced in the body does not exist` | The relative path is wrong; it resolves from the article's own folder. |
| `no cover image found … using a generated fallback` | Add `content/articles/<slug>.jpg` (warning only). |
| `taxonomy: no category mapping for "…"` | Add the name to `docs/data/blog-taxonomy.json`. |
| `modules: "…" is not a known module slug` | Use a slug from `/modules` (e.g. `finance`, `payroll`). |
| `front matter opened with "---" but never closed` | Add the closing `---` line. |

Build failures stop the build before `dist/` is written, so a broken article
can never be deployed.
